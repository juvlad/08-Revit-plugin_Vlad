# VladTools — плагин для Revit 2022, 2024 и 2025

Надстройка с вкладкой ленты **Vlad Tools**: панель «Семейства» — для работы в редакторе семейств (`.rfa`),
панель «Проект» — для работы в проекте (`.rvt`). Кнопки добавляются по одному образцу —
см. «Как добавить новую кнопку».

## Кнопки

### 3д миниатюра (панель «Семейства»)

Работает **только в редакторе семейств**. Создаёт 3D-вид с именем `3д миниатюра` и настраивает его:

| Настройка        | Значение                  | API                                                                                                              |
| ------------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| Аннотации        | выключены                | `View.AreAnnotationCategoriesHidden = true`                                                                    |
| Соединители    | скрыты                      | `SetCategoryHidden(OST_ConnectorElem + оси X/Y/Z)` и `HideElements` по самим `ConnectorElement` |
| Стиль графики | Реалистичный          | `DisplayStyle.Realistic`                                                                                       |
| Детализация    | Высокая (максимум) | `ViewDetailLevel.Fine`                                                                                         |

После создания вид открывается — так Revit возьмёт именно его как превью семейства при сохранении.

Повторное нажатие не создаёт дубликат: если вид `3д миниатюра` уже есть, к нему заново применяются настройки.
Если какую-то настройку применить не удалось (например, вид управляется шаблоном), остальные всё равно применяются,
а список проблем показывается в диалоге.

### Удалить параметры (панель «Семейства»)

Работает **только в редакторе семейств**. Удаляет из открытого (родительского) семейства
**отмеченные галочкой** общие параметры.

Порядок работы:

1. Кнопка открывает окно с таблицей **всех общих параметров** семейства: галочка, имя,
   «Экземпляр/Тип», «Размеры», группа, GUID.
2. Галочка **«Не показывать параметры, используемые в размерах»** стоит сразу и убирает из списка
   параметры, которыми помечены размеры. Такой параметр держит геометрию: удалить его — значит снять
   метку с размера и сломать параметрику. Снимите галочку, чтобы увидеть их — в столбце «Размеры»
   у них написано «Метка размера».
3. Галочки ставятся двумя способами, они дополняют друг друга:

   | Способ | Как |
   |---|---|
   | Вручную | щелчок по галочке слева от параметра; двойной щелчок по строке или пробел — то же самое, галочка в шапке — все сразу |
   | Правилом | поле выбора **«Отобрать параметры, начинающиеся с»** / **«Отобрать параметры, содержащие»** и строка правила, например `SP` |

4. Правило работает как поиск: подходящие строки остаются в таблице и сразу отмечаются, остальные из неё
   уходят. Галочка **«Инвертировать поиск»** переворачивает правило: «содержащие» + `ADSK` + инверсия —
   это все параметры, **кроме** ADSK-овских. Внизу пишется «Показано: N из M» и «Будет удалено: N
   из M показанных», на кнопке — счётчик.
5. После правила галочки правятся руками: лишнее снять, недостающее добавить. Правило само их больше не трогает.
6. Кнопка «Удалить (N)» запрашивает подтверждение со списком имён и удаляет параметры одной транзакцией
   (`FamilyManager.RemoveParameter`) — её можно откатить в Revit через Ctrl+Z.

Детали:

- **Удаляется только то, что показано в таблице.** Строка, ушедшая из списка — по правилу или как метка
  размера, — теряет галочку. Чтобы отметить что-то за пределами правила, сначала очистите строку правила.
- Пустая строка правила показывает весь список и не отмечает ничего — в том числе при включённой
  инверсии, иначе одна галочка убирала бы из таблицы всё разом. «Удалить» при этом заблокирована —
  чтобы «ничего не вписал» не означало «удалить всё».
- Регистр по умолчанию не учитывается; галочка «Учитывать регистр» включает точное сравнение.
- Столбцы сортируются щелчком по заголовку — галочки при сортировке сохраняются.
- Затрагивается только сам открытый документ семейства. Вложенные семейства не трогаются.
- Параметр, на который ссылается формула другого параметра, Revit удалить не даёт. Команда делает
  несколько проходов (сначала удалится тот, что ссылается, потом тот, на который ссылались),
  и только по-настоящему неудаляемые параметры попадают в итоговый список ошибок.

### Добавить формулы (панель «Семейства»)

Работает **только в редакторе семейств**. Задаёт параметрам открытого (родительского) семейства
формулы по списку, который хранится у пользователя и переезжает из семейства в семейство.

Порядок работы:

1. Кнопка открывает окно с таблицей «параметр — формула». В первый раз в ней уже стоят две формулы:
   | Параметр                     | Формула           |
   | ------------------------------------ | ------------------------ |
   | `ADSK_Размер_Диаметр` | `if (1=1,PI_DN,0)`     |
   | `ADSK_Масса`                  | `SP_Масса/1 кг` |
2. Своя формула вписывается по той же логике в пустую строку внизу таблицы: слева имя параметра,
   справа формула — ровно так, как она пишется в диалоге параметров Revit.
3. Каждая строка сразу проверяется по открытому семейству, результат — в столбце «Статус»:
   | Статус                               | Что значит                                                                                                                   |
   | ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
   | Готово к применению       | параметр есть, все имена из формулы тоже есть                                                    |
   | Формула будет заменена | у параметра уже стоит формула, новая её перезапишет                                        |
   | Параметр PI_DN не найден   | имени из формулы (или самого параметра из левого столбца) в семействе нет |
4. Кнопка «Применить (N)» задаёт **все отмеченные формулы одной транзакцией** — это и есть пакетное
   применение. Её можно откатить в Revit через Ctrl+Z. После этого показывается отчёт: что задано,
   что не получилось и почему.

Детали:

- Список сохраняется в `%AppData%\VladTools\formulas.txt` при каждом закрытии окна и подставляется
  в следующем семействе — одни и те же формулы второй раз вписывать не нужно. Файл можно править вручную.
- Если параметра из формулы нет, «Применить» показывает окно «Параметр PI_DN не найден». Когда часть
  формул в порядке, окно предлагает применить остальные; строки с ошибкой не применяются никогда.
- Снятая галочка оставляет формулу в списке, но не применяет её. В файле такая строка закрыта решёткой.
- Строка убирается из списка кнопкой «Удалить строку» (сначала выделить её в таблице).
- Имена сравниваются с учётом регистра — так же, как их читает сам Revit в формулах.
- Проверка формулы смотрит на имена, а не на смысл: ошибку в самой формуле поймает Revit при записи,
  и такая строка попадёт в отчёт об ошибках.
- Затрагивается только сам открытый документ семейства. Вложенные семейства не трогаются.

### Переименовать вложенные (панель «Семейства»)

Работает **только в редакторе семейств**. Пакетно переименовывает **вложенные** семейства открытого
семейства (и, если нужно, их типоразмеры). Имя самого открытого семейства не меняется — оно задаётся
именем файла.

Порядок работы, как в Excel:

1. Кнопка открывает окно со списком вложенных: «Что это», «Внутри семейства», «Текущее имя»,
   «Новое имя», «Экз.» (сколько экземпляров расставлено) и «Статус».
2. В поле **«Найти»** пишется кусок имени, в поле **«Заменить на»** — на что менять. Например,
   `DN` → `ДУ`: в столбце «Новое имя» сразу видно, что получится у каждой строки.
3. Отдельно можно дописать текст **в начало** и **в конец** имени — например приставку `(ФТ)-`.
4. Любая ячейка «Новое имя» правится руками: такая строка правилом больше не затирается.
5. Кнопка «Переименовать (N)» показывает список «старое → новое» и переименовывает всё
   одной транзакцией — её можно откатить в Revit через Ctrl+Z. Потом показывается отчёт.

Буфер имён (справа):

- Часто повторяющиеся куски имён (`(ФТ)-ФЛ_ГОСТ 33259-2015`, `ДУ`, `_ТИП 1`) сохраняются кнопкой
  **«Сохранить»** и лежат в `%AppData%\VladTools\names.txt` — они открываются в следующем семействе
  и переживают перезапуск Revit.
- Подставляются кнопками **«→ Найти»**, **«→ Заменить»**, **«→ В начало»**, **«→ В конец»**,
  а двойной щелчок вставляет значение в то поле, где стоял курсор.
- Файл можно править вручную: одна строка — одно значение, строка с решётки — комментарий.

Детали:

| Статус | Что значит |
| --- | --- |
| Будет переименовано | имя годное и отличается от текущего |
| Без изменений | новое имя совпало с текущим — строка пропускается |
| Имя уже занято | такое имя носит другое вложенное семейство (или другая строка списка) |
| Пустое имя, Revit не примет знаки: … | имя пустое или содержит `\`, `:`, `{`, `}`, `[`, `]`, `\|`, `;`, `<`, `>`, `?`, `` ` ``, `~` |

- Переименовывается только то, что показано в таблице. Поле **«Показывать»** переключает список:
  вложенные семейства, их типоразмеры или всё вместе; при переключении новые имена сбрасываются к текущим.
- Галочка слева включает строку в пакет; галочка в шапке — все сразу, пробел переключает выделенные строки.
- Регистр по умолчанию не учитывается: `dn` найдёт и `DN`. Галочка «Учитывать регистр» включает точное сравнение.
- Типоразмеры сравниваются на занятость имени внутри своего семейства, семейства — между собой.
- Обмен именами (`А` → `Б`, `Б` → `А`) делается в несколько проходов: пока имя занято соседом,
  которого тоже переименовывают, Revit его не отдаёт. Что не удалось — попадает в отчёт.
- Кнопка «Сбросить» очищает правило и возвращает все новые имена к текущим.

### Удалить общие параметры (панель «Проект»)

Работает **только в проекте** (`.rvt`). Удаляет из открытого проекта **отмеченные галочкой** общие параметры —
вместе с их значениями во всех элементах.

Для чего: после стадии П модель приходит с сотнями чужих общих параметров, и снимать их по одному
через «Управление → Параметры проекта» — часы работы. Здесь они сносятся пачкой по общему началу имени.

Порядок работы:

1. Кнопка открывает окно с таблицей **всех общих параметров проекта**: галочка, имя, «Экземпляр/Тип»,
   «Размеры», категории, группа, GUID.
2. Поле **«Показывать»** делит список на три вида:

   | Значение | Что попадает в таблицу |
   |---|---|
   | Все общие параметры | всё, что есть в файле |
   | Только параметры проекта | привязанные к категориям — те самые, что видны в «Управление → Параметры проекта» |
   | Только не привязанные | общие параметры, приехавшие с загруженными семействами или оставшиеся от снятых привязок |

3. Кнопка **«Проверить семейства (N)»** ищет параметры, которыми помечены размеры внутри загруженных
   семейств, — их удаление ломает геометрию. В проекте этого не видно, поэтому кнопка открывает каждое
   семейство по очереди: на большой модели это несколько минут, и Revit на это время перестаёт отвечать,
   о чём она предупреждает до начала. После проверки включается галочка **«Не показывать параметры,
   используемые в размерах»**, найденные параметры уходят из списка и теряют галочки, а в столбце
   «Размеры» у них написано «Метка размера».

   **Результат сохраняется** в `%AppData%\VladTools\dimensions\` — один файл на проект. В следующий раз
   окно открывается уже с проверкой, а на кнопке стоит число семейств, которых в ней нет: заново
   открываются только новые и изменившиеся, остальные берутся из файла. Внизу окна написано,
   когда проверка сделана.
4. Галочки ставятся так же, как в окне «Удалить параметры» для семейства: вручную (щелчок, двойной щелчок
   по строке, пробел, галочка в шапке — все сразу) или правилом **«Отобрать параметры, начинающиеся с»** /
   **«…содержащие»**, например `ADSK_` или `SP`. Правило работает как поиск: подходящие строки остаются
   в таблице и сразу отмечаются, остальные из неё уходят. Галочка **«Инвертировать поиск»** переворачивает
   правило: `ADSK` + инверсия — это все параметры, **кроме** ADSK-овских.
5. Кнопка «Удалить (N)» запрашивает подтверждение со списком имён и удаляет параметры одной транзакцией —
   её можно откатить в Revit через Ctrl+Z. Потом показывается отчёт.

Детали:

- Пока семейства не проверены, внизу окна так и написано, а подтверждение удаления отдельно предупреждает,
  что среди отмеченного может оказаться параметр, держащий геометрию.
- **Перезагрузили семейство и не сохранили проект — нажмите «Проверить заново».** Когда открывать больше
  нечего, кнопка меняет надпись на «Проверить заново (M)» и проходит все семейства мимо сохранённого
  результата. Это не придирка: Revit помечает семейство изменённым только при сохранении или синхронизации,
  поэтому перезагрузку внутри сеанса сохранённая проверка не замечает.
- Проверяются сами загруженные семейства. Вложенные в них семейства не открываются, контекстные
  и нередактируемые пропускаются; семейство, которое открыть не удалось, попадает в отчёт проверки,
  в сохранённый результат не идёт и остаётся непроверенным.
- Проект, который ещё ни разу не сохраняли, не кэшируется — проверку в нём придётся проходить заново.
  Файл проверки можно просто удалить, если нужно начать с чистого листа.
- **Удаляется только то, что показано в таблице.** Строка, ушедшая из списка — по правилу, по отбору
  «Показывать» или как метка размера, — теряет галочку. Чтобы отметить что-то за пределами правила,
  сначала очистите строку правила.
- Вместе с параметром пропадают его значения во всех элементах, а также поля спецификаций и фильтры видов,
  которые на него ссылались. Предупреждения об этом Revit не показывает по одному — они собираются
  и печатаются в итоговом отчёте.
- Пустая строка правила показывает весь список и не отмечает ничего — в том числе при включённой
  инверсии, иначе одна галочка убирала бы из таблицы всё разом. «Удалить» при этом заблокирована.
- Регистр по умолчанию не учитывается; галочка «Учитывать регистр» включает точное сравнение.
- Столбцы сортируются щелчком по заголовку — галочки при сортировке сохраняются.
- Параметр, который Revit удалить не даёт (например, его использует загруженное семейство), попадает
  в список ошибок отчёта; остальные из пачки удаляются как обычно.
- Не общие параметры проекта (созданные в самом файле, без ФОП и GUID) команда не показывает и не трогает.
- Затрагивается только сам проект: загруженные семейства и связи не меняются.

### Очистка (панель «Проект»)

Работает **только в проекте** (`.rvt`). Убирает из модели то, что отмечено галочками: чужое оформление
снимается разом, а не по одному узлу браузера.

Для чего: модель пришла со стороны и нужна только как геометрия — под неё не нужны ни чужие листы,
ни двести чужих видов, ни фильтры, ни семейства, которые нигде не стоят.

Окно предлагает восемь пунктов; у каждого в скобках — сколько нашлось **в этой** модели, а под заголовком
написано, что именно исчезнет. Пункт, которому убирать нечего, недоступен. Галочка **«Выбрать всё»** отмечает
все доступные пункты сразу.

| Пункт | Что убирает |
|---|---|
| Очистить неиспользуемые семейства | загруженные семейства и типоразмеры, на которые в модели нет ни одной ссылки; в скобках — число типоразмеров |
| Очистить все листы в модели | листы вместе с видовыми экранами, рамками и штампами; сами виды остаются в браузере, снятыми с листов |
| Очистить все фильтры в модели | всё из «Вид → Фильтры»: и фильтры видов с правилами, и фильтры выбора |
| Очистить все виды в модели | планы, планы потолков, разрезы, фасады, узлы, 3D, обходы, чертёжные виды |
| Очистить все легенды | виды-легенды вместе с компонентами на них |
| Очистить все спецификации | спецификации, ведомости материалов и примечаний, спецификации панелей |
| Очистить группы модели | **распускает** группы: элементы остаются на своих местах, исчезают только сами группы |
| Очистить неиспользуемые группы в модели | типы групп (модели, узлов, прикреплённых узлов), не размещённые в модели |

Кнопка «Очистить (N)» показывает список отмеченного и выполняет всё одной транзакцией — откатывается
она одним Ctrl+Z. Потом показывается отчёт: сколько чего убрано, что не удалось и какие предупреждения
Revit при этом погашены.

Детали:

- **Активный вид не удаляется никогда** — Revit не даёт удалить вид, на котором вы стоите. Если нужно снести
  и его, перейдите на другой вид и нажмите «Очистка» ещё раз.
- **Шаблоны видов не трогаются.** Не трогаются и служебные виды: браузеры, внутренние виды, отчёты расчётов,
  спецификация изменений внутри рамки листа, внутренняя спецификация ключевых примечаний — последние две живут
  не в браузере, а внутри рамки, и их удаление рамку ломает.
- **«Очистить группы модели» ничего не удаляет из модели.** Группы распускаются, элементы остаются на местах.
  Закреплённые группы при этом открепляются. Пустые типы групп после роспуска остаются висеть в браузере —
  их уберёт пункт «Очистить неиспользуемые группы»: отмечайте оба сразу.
- **Порядок работы отличается от порядка пунктов в окне.** Сначала уходит оформление, потом группы, и только
  в конце — неиспользуемые семейства: к этому моменту ненужными успевают стать ещё и рамки листов, марки
  и узловые элементы, и они уходят той же пачкой. Поэтому семейств удалится обычно больше, чем показано
  в скобках при открытии окна.
- **Семейство, на которое в модели остались ссылки, не удаляется**, даже если по подсчёту оно свободно:
  перед удалением команда переспрашивает Revit, не уйдут ли вместе с типоразмером размещённые элементы.
  Сколько таких оставлено, написано в отчёте.
- Подсчёт неиспользуемых семейств обходит все элементы модели, поэтому на большом файле окно открывается
  не мгновенно.
- Что Revit удалить не дал, попадает в список ошибок отчёта; остальное из пачки убирается как обычно.
- Затрагивается только сам проект: загруженные семейства изнутри не меняются, связи не трогаются.

### Link Manager (панель «Проект»)

Работает **только в проекте** (`.rvt`). Связывает с ним сразу пачку моделей — с диска, с Revit Server
и из BIM360/Autodesk Docs — с одним размещением и одной настройкой рабочих наборов на всё.

Для чего: в самом Revit каждая связь вставляется своим диалогом, и в каждом заново выбирается
«По общим координатам» и заново снимаются галочки с «00_Shared levels and grids». На двадцати связях
это двадцать одинаковых диалогов подряд.

**Откуда брать модели.** Четыре кнопки сверху, всё складывается в одну таблицу:

| Кнопка | Что открывает |
|---|---|
| Файлы… | обычный выбор файлов: диск, сетевая папка; можно отметить сразу несколько |
| Revit Server… | дерево папок сервера с галочками у моделей; имя сервера вводится один раз и запоминается |
| BIM360… | учётные записи, проекты и папки Autodesk Docs — теми глазами, которыми на них смотрит ваша учётная запись |
| BIM360 по GUID… | список моделей парой GUID — на случай, когда просмотр недоступен |

Для BIM360 **отдельно входить никуда не нужно**: плагин берёт тот вход, под которым вы уже сидите в Revit.
Если в учётную запись Autodesk вы не вошли, кнопка так и скажет и предложит ввод по GUID. В облаке видны
только совмещённые модели: обычный `.rvt`, просто положенный в папку, связать нельзя — это ограничение Revit,
а не плагина.

**Наборы связей.** Собранный список сохраняется в профиле Windows под своим именем («Смежники», «Стадия Р»)
и в следующем проекте подставляется целиком одной кнопкой. Для BIM360 это главный способ работы: сохранённый
набор грузится и тогда, когда до облака не достучаться.

**Размещение** выбирается одно на все связи: «По общим координатам», «Совмещение внутренних начал»,
«Центр в центр» или «По расположению площадки проекта». Рядом — тип связи (наложение или прикрепление)
и относительный путь (только для файлов: у Revit Server и облака путь всегда абсолютный).

**Рабочий набор проекта**, в который положить саму связь, выбирается **у каждой связи отдельно** —
столбец «Набор проекта» в таблице: АР кладём в «01_Связи_АР», КР в «01_Связи_КР». Если набор для всех
один, есть поле «Класть связи в рабочий набор проекта» и кнопка «Задать отмеченным». Выбор сохраняется
вместе с набором связей, так что в следующем проекте расставлять заново не придётся. В несовмещённом
проекте столбца нет — там и рабочих наборов нет.

**Подбор набора по имени модели.** Галочка «Подбирать по имени модели» рядом с полем набора: плагин
берёт код раздела из имени файла (`Корпус1_OV_R22.rvt` → `OV`) и ставит новой связи набор проекта,
в имени которого этот код стоит отдельным словом — `01_Link_OV`, `01_Связи_OV`. Суффикс версии
(`_R22`, `_R24`) отбрасывается сам. Если подходящих наборов несколько — плагин не гадает, а пишет
об этом в «Состоянии», выбор за вами. Подбор только заполняет пустые строки: набор, выбранный руками
или пришедший из сохранённого набора связей, не трогается; уже стоящие в проекте связи — тоже.
Список кодов разделов лежит в `%AppData%\VladTools\links\_settings.txt` (строки `DISCIPLINE`) —
туда можно дописать свой код или строку с кириллицей.

**Рабочие наборы внутри связей** — наоборот, одни на все связи. Внизу окна список имён с галочками: отмеченные
наборы закроются в каждой связи. Имена берутся из прошлого раза, так что «00_Shared levels and grids»
обычно уже отмечен при открытии; кнопка «Прочитать наборы» дочитывает имена из самих моделей, не открывая их.

Столбец «Где есть» — это и есть проверка имени, и смотреть в него стоит всегда, когда набор
«почему-то не закрылся». «в N связях» — набор найден и будет закрыт. «нет ни в одной» — имя
отмечено, но у смежников набор назван иначе: закрывать нечего, и Revit тут ни при чём.
«из прошлого раза» — имя просто ещё не сверяли: отметьте связи и нажмите «Прочитать наборы».
Про имена, которых не нашлось ни в одной связи, плагин теперь пишет и в итоговом отчёте.
Рядом — правило: «начинающиеся с» + `00_` закроет набор и там, где он назван «00_Общие уровни и оси».
Правило работает **при загрузке, для каждой связи отдельно**, а не только по кнопке «Отметить».
Поле «При загрузке» переключает базу: открыть все наборы (тогда галочка значит «закрыть»),
закрыть все (галочка значит «открыть») или как при последнем открытии модели.

Кнопка «Загрузить (N)» показывает, что именно произойдёт, и выполняет всё пачкой. Потом — отчёт:
что связано, что не получилось, что вышло с рабочими наборами и какие предупреждения Revit при этом
погашены.

После загрузки плагин **сам проверяет, что стало с наборами в каждой связи**, и пишет в отчёте одно
из четырёх: тишина — всё закрылось как просили; «помогла повторная загрузка» — с первого раза Revit
не послушался; строка в «Не получилось» с именами наборов — не послушался и со второго; «Наборы
заказаны, но проверить их не удалось» — связь не дала себя перечитать, и состояние наборов надо
посмотреть глазами. Раньше последний случай выглядел как успех, поэтому незакрытые наборы можно было
не заметить.

Детали:

- **Новые связи сразу закрепляются булавкой** — чтобы их нельзя было случайно сдвинуть.
  Снять закрепление в Revit можно одной кнопкой; уже существующие связи плагин не трогает.
- **Связи, которые в проекте уже есть, показаны в той же таблице** со статусом «Уже в проекте»,
  и в столбце «Набор проекта» видно, где они сейчас лежат. Трогать их необязательно, но если отметить —
  они перезагрузятся с новой настройкой рабочих наборов, а при смене набора проекта переедут в него
  вместе со всеми своими экземплярами.
  Размещение у существующей связи не поменяется: Revit этого не позволяет, связь нужно удалить и завести заново.
- **Перезагрузка существующих связей стирает историю отмены.** Так устроен Revit: перезагрузка связи
  чистит весь список «Отменить». Поэтому она делается первой, а новые связи заводятся после неё —
  их Ctrl+Z вернёт. А вот то, что вы делали в проекте до нажатия кнопки, после перезагрузки уже не отменить.
  Окно предупреждает об этом перед началом; если отмечать только новые связи, история не трогается.
- **Иногда Revit не применяет настройку наборов с первого раза — плагин это лечит сам.**
  Revit может отчитаться об успехе и всё равно оставить наборы как были. Плагин перечитывает уже
  загруженную связь и, если Revit не послушался, пробует ещё раз; об этом напишет в отчёте:
  «помогла повторная загрузка» (она тоже стирает историю отмены) — либо, если не помогло и со
  второго раза, обычная строка в «Не получилось» с именами наборов, которые остались не так.
- **Наборы внутри вложенных связей закрыть нельзя.** Это ограничение самого Revit, не плагина:
  если у смежника внутри его модели стоит своя подоснова, её уровни и оси останутся видны, чем бы
  вы их ни закрывали. Тут помогает только правка у смежника.
- **Наборы можно настроить только в момент загрузки связи.** Поэтому смена настройки у связи,
  которая уже стоит в проекте, делается перезагрузкой — со всеми её последствиями для истории
  отмены (см. выше). Аналога кнопки Revit «Manage Links → Manage Worksets», меняющей наборы
  на месте, в API нет.
- **Работает только то, что показано в таблице**: строка, ушедшая из неё по фильтру «Показывать», теряет галочку.
- Дубли отбрасываются сами: модель, которая в таблице уже есть, второй раз не добавится, а в дереве просмотра
  будет серой и без галочки.
- Чтение папок сервера и облака идёт по сети, поэтому первое раскрытие большой папки занимает секунду-другую.
  Если служба не ответила, окно не закроется — причина появится красной строкой внутри той самой папки.
- **Набор проекта из сохранённого списка сверяется с текущим проектом.** Наборы у каждого проекта свои;
  если такого набора здесь нет, строка встанет в «(активный)», а в «Состоянии» будет написано, какого
  набора не хватило.
- Настройки (размещение, тип связи, отмеченные наборы, правило) сохраняются при **любом** закрытии окна,
  в том числе по «Закрыть» и Esc.

### Авто размеры (панель «Проект»)

Работает **только в проекте** (`.rvt`), на **плане этажа**. Расставляет по сторонам выбранных помещений
те же нитки размеров, что вы один раз поставили вручную вдоль одной стены — типовая работа для
кладочных планов АР.

Порядок работы:

1. Выделите готовые размеры вдоль одной стены одного помещения (габарит, ширины проёмов, оси проёмов,
   ширину примыкающих перегородок — что нужно, необязательно всё сразу) и нажмите кнопку. Если выделены
   ещё и помещения — они и станут областью расстановки; если нет, окно предложит взять все помещения
   активного плана.
2. В открывшемся окне нажмите **«Взять образец…»** и выделите те самые размеры, «Готово». Окно закроется,
   а откроется заново уже с разобранной таблицей: у каждой строки — вид нитки, смещение от стены
   (в мм) и тип размера.
3. Разбор — это подбор, не точный расчёт: строку всегда можно поправить руками (сменить вид нитки
   в выпадающем списке, поправить смещение, тип размера), добавить свою кнопкой «Добавить нитку»
   или убрать лишнюю.
4. Сверху — **«Граница помещения»** (по умолчанию «По граням несущего слоя», как и нужно для кладочного
   плана) и **«Ставить размеры»** (внутрь помещения или наружу — одна настройка на весь набор ниток).
5. Кнопка **«Расставить (N)»** ставит нитки по всем сторонам всех выбранных помещений одной транзакцией —
   откатывается она одним Ctrl+Z. Повторный запуск на тех же помещениях не удваивает размеры: прежние,
   поставленные этой же кнопкой, сначала убираются (галочка «Удалять ранее расставленные этой кнопкой»
   позволяет это отключить). Размеры, поставленные вручную, кнопка не видит и не трогает никогда.

Виды ниток:

| Вид | Что засекает |
|---|---|
| Габарит | только два крайних угла стороны |
| Проёмы | углы стороны + грани откосов всех дверей и окон на ней |
| Оси проёмов | углы стороны + оси проёмов (доступно, только если семейство публикует осевую плоскость) |
| Перегородки | углы стороны + грани перегородок, примыкающих к ней изнутри помещения |
| Грани стен | углы + стыки стен внутри стороны (для стороны, собранной из нескольких стен подряд) |
| Всё вместе | проёмы + оси проёмов + перегородки на одной нитке |

**Шаблоны.** Набор ниток сохраняется кнопкой «Сохранить шаблон» в `%AppData%\VladTools\autodim\` и
переносится в другой проект: там своя таблица типов размеров, поэтому тип хранится именем, а не Id —
если такого типа в проекте нет, применится текущий тип по умолчанию, о чём будет написано в «Состоянии».

Детали:

- Сторона, собранная из криволинейной стены, пропускается — авторазмеры работают только по прямым
  участкам.
- Нитка, которой на конкретной стороне нечего засекать (например, «Оси проёмов» на стороне без проёмов),
  на этой стороне просто пропускается — с причиной в итоговом отчёте, остальные нитки и стороны это не трогает.
- Затрагивается только активный план этажа открытого проекта; связанные модели не трогаются.

```
    RoomSideBuilder.cs           строит стороны из GetBoundarySegments помещения
    DimensionReferenceCollector.cs  сторона + вид нитки → ссылки для NewDimension
    DimensionSampleReader.cs     разбор образцовых размеров в шаблон ниток
    DimensionTemplate.cs         шаблоны авторазмеров и настройки окна (%AppData%)
    AutoDimensionMarker.cs       метка «этот размер поставила кнопка» (ExtensibleStorage), от повторов
  Resources/                     PNG-иконки 16×16 и 32×32 (вшиты в DLL)
```

## Сборка и установка

```powershell
.\build.ps1
```

Требуется .NET SDK и установленный Revit — версия задаётся `RevitVersion` (по умолчанию `2022`, из
`Directory.Build.props`; оттуда берутся `RevitAPI.dll` и `RevitAPIUI.dll`). Целевой фреймворк зависит от года:
`net48` для 2022 и 2024, `net8.0-windows` для 2025 (Revit 2025 сам работает на .NET 8).

`.\build.ps1` без параметров собирает и ставит **все три года за один запуск**, пропуская те, что не
установлены на машине. Собрать только один год:

```powershell
.\build.ps1 -RevitVersion 2024
dotnet build src\VladTools\VladTools.csproj -c Release -p:RevitVersion=2024   # то же напрямую
```

После сборки файлы уходят в `%AppData%\Autodesk\Revit\Addins\<год>\`:

- `VladTools.addin`
- `VladTools\VladTools.dll`

Revit нужно перезапустить. Если Revit был открыт во время сборки, DLL заблокирована — закройте его и соберите заново.

Собрать без установки: `.\build.ps1 -NoDeploy` (или `-p:DeployToRevit=false` при прямом вызове `dotnet build`).

Удалить плагин: удалить `VladTools.addin` и папку `VladTools` из `%AppData%\Autodesk\Revit\Addins\<год>\`.

## Как добавить новую кнопку

1. Новый класс в `src/VladTools/Commands/`:

```csharp
[Transaction(TransactionMode.Manual)]
public class МояКомандаCommand : IExternalCommand
{
    public Result Execute(ExternalCommandData commandData, ref string message, ElementSet elements)
    {
        // ...
        return Result.Succeeded;
    }
}
```

2. Иконки `Resources/имя_16.png` и `Resources/имя_32.png` (необязательно — без них кнопка будет без картинки).
3. Регистрация в [App.cs](src/VladTools/App.cs) рядом с существующей кнопкой:

```csharp
Ribbon.AddPushButton(panel,
    name: "VladTools_МояКоманда",
    text: "Моя\nкоманда",
    commandType: typeof(МояКомандаCommand),
    tooltip: "Что делает кнопка",
    iconBaseName: "имя");
```

Для новой панели: `var panel2 = Ribbon.GetOrCreatePanel(application, TabName, "Название панели");`

## Перенос на другую версию Revit

Год не прописывается в csproj руками — это ключ сборки `-p:RevitVersion=<год>` (`.\build.ps1 -RevitVersion <год>`
или `dotnet build -p:RevitVersion=<год>`), от него зависят пути к `RevitAPI.dll`, папка установки и целевой
фреймворк. `RevitServerClient.ServiceVersion` тоже правки не требует — год Revit Server подставляется
из запущенного Revit сам, при старте надстройки.

Для 2022, 2024 и 2025 всё уже сделано — подробный разбор, что изменилось и что для очередного года
проверить в первую очередь, в [CHECKLIST-Revit2024.md](CHECKLIST-Revit2024.md) и
[CHECKLIST-Revit2025.md](CHECKLIST-Revit2025.md). Для года после 2025 одной пересборки может снова
не хватить, если Autodesk опять сменит рантайм — как это уже случилось при переходе на 2025
(`net48` → `net8.0-windows`); смотреть `RevitAPI.runtimeconfig.json` рядом с `RevitAPI.dll` нового года.
